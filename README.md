# Detecting-AI-Generated-Songs-with-Spectral-Fakeprints

A simple detector for AI-generated music (Suno, Udio, ...) that uses only
spectral information. Each track is turned into a one-dimensional "fakeprint"
feature, and a logistic regression classifier separates real from fake songs.

Homework 2 for the course Computer Music - Representations And Models (CMRM) at Politecnico di Milano.

Authors: Martina Luyten and Andrea Casati

## Idea

Many neural audio generators work on spectrograms, using convolution and
deconvolution layers (for example diffusion U-Nets or spectrogram autoencoders).
They tend to leave systematic spectral artifacts, such as grid-like or
checkerboard patterns and unusual high-frequency structure. Classical Fourier
tools can pick these up, so a detector does not need a deep network.

## Data

A balanced subset of the [SONICS](https://github.com/awsaf49/sonics) dataset, a
collection built for detecting synthetic songs, with real tracks and tracks
generated by commercial systems such as Suno and Udio.

- Training set: 485 real and 485 fake tracks (perfectly balanced, so the
  classifier is not biased towards one class)
- Test set: 515 tracks, with the labels hidden until the end
- Mono audio at 22,050 Hz

## Method

1. **Look at the data.** Compare waveforms, FFT and STFT spectrograms of one real
   and one fake track.
2. **Fakeprint feature.**
   - Compute the STFT (`n_fft = 4096`, `hop = 1024`) and take the power
     spectrogram.
   - Convert it to dB and average it over time, giving one spectral profile
     per track.
   - Estimate the lower envelope of that profile in a chosen frequency range
     (default 0-16 kHz) and measure how far the profile rises above it.
   - Normalise the result to [0, 1].
3. **Classifier.** Train a scikit-learn `LogisticRegression` on the fakeprint
   vectors.
4. **Evaluate.** Predict on the test set, compare with the ground-truth labels,
   and inspect the learned coefficients.

## What we found

### Listening and spectra
- The real and fake examples are in different genres (hip-hop vs.
  singer-songwriter pop), so listening alone does not make the difference
  obvious. The clearest audible cue is **transients**: the real track has sharp
  ones, while the fake track has long reverbs and softer attacks.
- In the FFT, the fake track has **no content above about 7.5 kHz**, whereas the
  real track extends almost to Nyquist. The fake track also has more low-frequency
  energy. These differences can come from production choices as well, so the
  FFT alone does not prove where a track comes from.
- In the STFT, the real track shows stable horizontal lines (harmonics), and the
  fake track shows narrower vertical stripes. These vertical patterns are less
  typical of natural recordings and are a possible sign of generation.

### Properties of the fakeprint
- It does not depend on the track's level, because of the dB scale, the
  comparison with a lower envelope and the normalisation. A louder or quieter
  copy of the same track gives the same curve.
- A peak of 1 marks the strongest deviation from the smooth baseline. A mostly
  flat curve means the spectrum follows its envelope with no regular
  artifacts, as in natural recordings.
- The frequency range matters. Restricting it to 0-5 kHz instead of 0-16 kHz
  makes the real and fake curves much more similar, because the high-frequency
  artifacts are left out.
- In our examples the fake curve has few peaks along the envelope at low
  frequencies, and its peaks disappear at high frequencies, which matches the
  7.5 kHz cut-off seen in the FFT.

### Classifier results
- **Training set:** 100% accuracy, with all 485 real and 485 fake tracks correct.
  This looks perfect, but it could also be overfitting. Moving the decision
  threshold to 0.3 or 0.7 changed nothing on the training set, which means the
  predicted probabilities are far from the uncertain middle.
- **Test set:** about **99.6% accuracy** (509 true negatives, 4 true positives,
  2 false positives, 0 false negatives). The classifier found all 4 real
  tracks. The 2 false positives are fake tracks that sound realistic and have
  weak artifacts.
- A different threshold is unlikely to help. The default already finds every
  real track with only 2 false alarms, and lowering it would mostly add false
  positives.

### Which frequencies matter?
- Below about 7.5 kHz, the largest positive and negative coefficients are
  spread across the range, with no single dominant band. The classifier relies
  on fine-grained patterns there.
- Above about 7.5 kHz, all coefficients are non-negative. High-frequency
  activity therefore only counts as evidence for "real" and never for "fake".
  This is surprising, because the fake tracks sound "noisy" or "ethereal" in
  the highs, but the structured high-frequency activity that the fakeprint
  captures is more typical of real recordings.

### Limitations
- The test set has very few real tracks (4 out of 515), so the accuracy is
  optimistic.
- The detector depends on spectral artifacts. It may fail on audio without
  high-frequency content, or as generators learn to produce more realistic
  spectra. Combining it with other features could help.

## How to run

The dataset and a helper file from the assignment are **not** included here.

1. Download the SONICS subset provided by the course and place it next to the
   notebook as:
   ```
   sonics/
   ├── train/fake/
   ├── train/real/
   ├── test/
   └── ground_truth.csv
   ```
2. Put `utils.py` (functions `lower_envelope`, `max_normalise`, `curve_profile`,
   provided with the assignment) in the same folder.
3. Install the dependencies:
   ```
   pip install numpy scipy pandas matplotlib scikit-learn librosa tqdm mutagen jupyter
   ```
4. Open `Luyten_Casati.ipynb` and run all cells. Computing the features for all
   tracks takes several minutes.
